# farert CLI(test/unix/all/farert)の使い方

`app/alps/alpdb.cpp`(C++ 経路・運賃エンジン)を CLI で動かすテストツール。
ソースは `test/unix/all/testmain.cpp`(引数解析)と `test/unix/common/test_exec.cpp`
(`test_route()` / `test_autoroute()` / `test_exec()`)。
**オプションの意味は `usage()` 表示や `CLAUDE.md` の説明と一部食い違う**。本スキルはソースと実行結果で確認した内容(2026-10)。

## ビルドと準備

```bash
cd test/unix/all
make                      # test/unix/common/Makefile を使う。-D_DEBUG -DALPS_LOG -O0 のデバッグビルド
source start.sh           # export farertDB=<repo>/db/jrdbNewest.db
# start.sh を使わない場合(別ディレクトリから呼ぶ等)
export farertDB=$(cd ../../../db && pwd)/jrdbNewest.db
```

- `farertDB` が未設定だと `Should be set environment variable the 'farertDB'...` で即終了する。
- `alpdb.cpp` を変更したら `make` し直す(依存は Makefile が追う)。全部作り直すときは `make clean && make`。

## 起動モード

引数の**語数**(オプションを除く)でモードが決まる。

| 呼び方 | モード | 例 |
|---|---|---|
| 引数なし | usage を表示して終了(rc=-1)。全テストは走らない | `./farert` |
| `-exec` | 全テスト経路(約1783経路)を計算し、カレントディレクトリに `test_result.txt` を出力 | `./farert -exec` |
| 1語(ファイルパス) | ファイルの各行を1経路として実行 | `./farert routes.txt` |
| 奇数語 `駅 路線 駅 ...` | 経路を明示して計算(`test_route`) | `./farert 新大阪 山陽新幹線 姫路` |
| 偶数語 `[駅 路線 駅 ...] 着駅` | 末尾の駅まで最短経路を自動探索(`test_autoroute`) | `./farert 東京 大阪` |

自動経路探索は、末尾1語を着駅、それより前を「途中まで指定した経路」として、その先を最短経路でつなぐ。
例: `./farert 東京 東海道線 品川 大阪` は 品川 までを確定し、品川→大阪 を探索する。

### 経路ファイルの書式

```text
# '#' で始まる行と空行は読み飛ばす
新大阪 山陽新幹線 姫路      # 奇数語 = 経路を明示
東京 大阪                   # 偶数語 = 自動経路探索
/                           # '/' で始まる行で読み込み終了(以降は無視)
品川 京都
```

- 行中の `#` 以降もコメントとして除去される。
- オプション(`-1` 等)はファイル内の全行に同じ値が使われる。

## オプション `-<数値>[r]`

オプションは**1つだけ**指定できる(先頭の1語のみ解析)。数値の意味はモードで異なる。

### 経路明示(奇数語)のとき: 表示を抑制するビットフラグ

| ビット | 意味 |
|---|---|
| 1 | 反転(逆方向)の計算を出さない |
| 2 | `///既定`(規則適用後)を出さない |
| 4 | `///非適用`(規則を適用しない運賃)を出さない |

| 値 | 結果 |
|---|---|
| なし / `-0` | 既定 + 非適用 + 反転 すべて |
| `-1` | 反転なし |
| `-4` | 非適用なし(**逆方向の計算ではない**。CLAUDE.md の「-4 で逆経路」は誤り) |
| `-5` | 既定のみ・反転なし。**1経路の運賃だけ見たいときはこれ** |
| `-2` / `-3` / `-6` / `-7` | 実用上ほぼ空。`///非適用` の判定(`rule_en()`)が運賃計算後でないと真にならないため、既定を抑止すると非適用も出ない |
| `r`(`-r`, `-5r` 等) | 指定した語順を逆にして読み込む(着駅から発駅へ書いた経路を入力する用) |

### 自動経路探索(偶数語)のとき: 使う線区(数値 % 4)

| 値 | 探索対象 | 出力の見出し |
|---|---|---|
| なし / `-0` / `-4` | 在来線のみ(新幹線・会社線を使わない) | `auto route(新幹線も在来線も使わない)`(見出しの文言は誤記) |
| `-1` / `-5` | 新幹線も使う | `auto route(新幹線使用)` |
| `-2` / `-6` | 会社線も使う | `auto route(会社線使用)` |
| `-3` / `-7` | 新幹線も会社線も使う | `auto route(新幹線も会社線も使う)` |

`usage()` の「1: zairaisen only, 2: with shinkansen ...」はずれているので信用しない。
`r` は自動経路探索では無効。

## 出力の読み方

結果は **stdout**、TRACE(内部ログ)は **stderr**。運賃だけ見るなら `2>/dev/null`。

```text
!****<01>: ******************* 結果 **********************
<新大阪 山陽新幹線 姫路 >          ← 入力経路

///既定                            ← 規則(86/87/88/69/70/160条、114条等)適用後の運賃
新大阪 -> 姫路
経由：[山陽新幹線]
営業キロ： 87.9 km
運賃： ¥1,460       往復： ¥2,920
...
///非適用                          ← 規則を適用しない場合(規則が効いた経路のみ出る)
...
旅客営業規則第88条を適用していません
------ 反転 ------                 ← 以降は逆方向
```

経路によって次のブロックが追加で出る(いずれも `test_route()` 内):

| 見出し | 出る条件 |
|---|---|
| `///着駅=単駅` / `///発駅=単駅` | 名阪間の都区市内発着選択が可能 |
| `///JR東海株主優待券使用` / `未使用` | JR東海株主優待券が使える |
| `///指定経路` / `///最安経路` | 近郊区間内で指定経路(大回り)と最安経路を選べる |
| `///旅客営業取扱基準規程115条(...)` | 115条の特定都区市内発着を選べる |
| `------ 反転は無効---...` | 逆方向にできない経路 |

自動経路探索は `!===<00>: auto route ===` → `* pre route` → `* auto route(...)` → `arg=<探索種別>` → `///既定` の順。
経路が作れないと `Can't route.(OK|NG), rc=<n>`。

## ASSERT と終了待ち

デバッグビルドなので、エラー経路(存在しない駅・路線の組み合わせ等)では
`!!!Assertion error!!! <file>:<line> ... Press enter key to continue.` を出して **stdin を待つ**。
バッチ実行や Claude からの実行では必ず `</dev/null` を付ける(EOF で処理を続行する)。

```bash
./farert -5 新大阪 山陽新幹線 姫路 2>/dev/null </dev/null
```

`Assertion error` が出たら、入力経路が不正(駅が路線上に無い等)か、エンジンの不具合を疑う。

## よく使う実行例

```bash
cd test/unix/all && source start.sh

# 1経路の運賃だけ(TRACE 抑止、ASSERT で止めない)
./farert -5 長万部 函館線 森林公園 2>/dev/null </dev/null

# 規則適用前後を比較(往復は不要)
./farert -1 東京 東海道線 熱海 2>/dev/null </dev/null

# 新幹線も使って最短経路を探索
./farert -1 東京 大阪 2>/dev/null </dev/null

# 内部トレースを見る(114条・86/87条の判定など)
./farert -5 長万部 函館線 森林公園 2>trace.log </dev/null
grep -E 'Rule 114|checkOfRule114j|judgementOfFare' trace.log

# 経路ファイルを一括実行して保存
./farert routes.txt > log.txt 2>&1 </dev/null

# 全テスト経路を流して test_result.txt を作り直す(約30秒)
./farert -exec > exec.log 2>&1 </dev/null
```

## zsh での注意

- 変数に入れた経路は単語分割されない。`r="新大阪 山陽新幹線 姫路"; ./farert ${=r}` のように `${=r}` を使う。
- `echo ====` は `=cmd` 展開でエラーになる。区切り線は引用符で囲む(`echo "===="`)。
